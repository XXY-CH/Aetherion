# Feature Research: Aetherion

## Table Stakes For V1

- TUI command surface.
- Local workspace identity.
- Contract validation over schemas and examples.
- Event Ledger append.
- Tool request creation.
- Policy decision.
- Scoped lease issuance.
- Local file read/write through policy.
- Observation and verification records.
- Trace replay reconstruction without live side-effect repetition.
- Runtime state ignored by git.
- Tests proving the local kernel loop.

## Differentiators

- Capability Capsules instead of unrestricted skills.
- Event-driven proactive Opportunity Lifecycle instead of cron-style interruption.
- Dreaming as reviewable memory/capability/eval/policy patches.
- Human-readable source of truth with rebuildable indexes.
- Migration reports that import OpenClaw/Hermes evidence but not authority.
- Rust Local Supervisor authority boundary.
- Computer Use adapters that remain sibling execution targets behind policy.
- Connector imports quarantined by default.

## Anti-Features

- GUI-first product before TUI kernel proof.
- Real IM delivery before outbox and policy gates.
- Browser extension as authority boundary.
- Connector authorization treated as agent permission.
- Generated packages running inside Local Supervisor.
- Raw secrets in configs, examples, memory, logs, traces, or fixtures.
- Replay that repeats live side effects by default.
- Dreaming that directly mutates active memory, capability, policy, or external systems.

## Feature Dependencies

- Rust supervisor IPC depends on stable TypeScript contract examples.
- Computer Use runtime depends on policy decisions, scoped leases, taint propagation, verifier anchors, and replay records.
- Connector runtime depends on vault references, migration reports, idempotent inbox/outbox, and policy gating.
- Memory OS depends on Event Ledger source events, Memory Candidates, and patch review lifecycle.
- Capability Capsules depend on manifest schemas, replay tests, sandbox trials, scoring, and rollback metadata.
