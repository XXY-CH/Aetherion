## Naming Status

Aetherion is a codename, not a cleared public name.

Supplied research indicates possible collision risk across:

- Existing GitHub projects using Aetherion for agent orchestration.
- A PyPI package named `aetherion`.
- Trademark records around AETHERION AI.
- An existing `aetherion.io` platform with adjacent enterprise AI workflow positioning.

Do not make irreversible brand, domain, package, or trademark decisions around Aetherion until a clearance pass is complete.

## Sharp Differentiation

OpenClaw solves: "How do I message my agent from anywhere?"

Hermes solves: "How does my agent learn skills?"

OpenHuman solves: "How does my agent understand me?"

Aetherion's intended product solves: "How can an agent safely, auditably, and evolvably act for me across devices, tools, memory, and workflows?"

## Product Moat

1. Capability Capsule replaces ungoverned skills and plugins.
2. Event-driven Proactive replaces cron-style proactive loops.
3. Dreaming produces reviewable patches, not actions.
4. Human-readable files are source of truth; indexes are rebuildable projections.
5. User Boundary Layer is a first-class kernel concern.
6. Tool Policy Proxy is the only access and action entry for sensitive reads, data egress, and side effects.
7. Import is migration, not trust inheritance.
